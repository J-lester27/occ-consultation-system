# One Cainta College — Student Consultation & Appointment Management System

A Java Swing desktop app built for the Data Structures & Algorithm Analysis final
project. It implements all three roles (Student, Professor, Admin) from the
requirements sheet, using the required data structures and algorithms, with
data saved to CSV files so nothing is lost between runs.

## How the requirements map to the code

| Requirement | Where it lives |
|---|---|
| Array/List — student & professor records | `DataStore` (`List<Student>`, `List<Professor>`) |
| Queue — FIFO consultation requests | `structures/MyQueue.java`, used in `DataStore.requestAppointment` / `acceptAppointment` |
| Stack — recent completed/cancelled transactions | `structures/MyStack.java`, used in `DataStore.completeAppointment` / `cancelAppointment` / `rejectAppointment` |
| Linked List — consultation history | `structures/MyLinkedList.java`, `DataStore.historyList` |
| Hash Table — search students by ID | `java.util.Hashtable<String,Student>` in `DataStore.studentIndex` |
| Tree — organize records for search/sort | `structures/AppointmentBST.java` (binary search tree keyed by date+time) |
| Searching algorithm | `util/Algorithms.java` — `linearSearchStudentById`, `searchAppointments`, `binarySearchByDateTime` |
| Sorting algorithm | `util/Algorithms.java` — hand-written **Quick Sort** (`sort`, by date/time, student name, professor name, or status) |
| Queue algorithm | `DataStore` — requests are enqueued on submission and dequeued as professors act on them |
| Stack algorithm | `DataStore.getRecentTransactions()` — LIFO retrieval of the most recent transactions |
| Validation algorithm | `util/Algorithms.validateRequest` — checks date/time format, no past dates, professor slot exists, no double-booking |

All data is persisted as plain CSV under `/data` via `util/FileManager.java`.

## Opening the project in NetBeans

The GUI screens are hand-written Swing code (not generated by the drag-and-drop
GUI Builder), so you won't get the "Design" view for these forms — but the
project runs perfectly as a normal Java application, and you can still edit
the Java code directly in NetBeans, set breakpoints, etc.

1. Open **NetBeans**.
2. **File → New Project…**
3. Choose **Java with Existing Sources** (under the *Java* category) → Next.
4. **Project Name**: `FinalProject`. Project location: choose where
   you unzipped this folder. Uncheck "Use Dedicated Folder" if asked, or just
   point it at this folder. Next.
5. **Source Package Folders** → click **Add Folder…** → select the `src`
   folder inside this project → Next → Finish.
6. In the **Projects** panel, right-click the project → **Properties →
   Run** → set **Main Class** to `consultation.Main` (or use "Browse…" and
   pick it).
7. Right-click the project → **Clean and Build**, then **Run**.

Alternatively (simplest): **File → New Project → Java Application**, name it
`FinalProject`, finish, then delete the generated `src` folder
NetBeans creates and copy this project's `src` folder in its place. Set
`consultation.Main` as the main class as above.

> Make sure the `data` folder sits in the project's working directory (the
> project root) — that's where NetBeans runs the app from by default, and
> it's where the CSV files live/get created automatically on first run.

## Logging in

- The first time the app runs, it auto-creates a default admin account:
  - **Username:** `admin`  **Password:** `admin123`
- Use the **Register** button on the login screen to create Student or
  Professor accounts.
- As a Professor, go to **Manage Schedule** to open consultation slots
  (date + time) before students can request them.
- As a Student, go to **Request Consultation**, pick a professor, pick one
  of their open slots, and submit — it lands in that professor's request
  queue as **PENDING**.
- As a Professor, **Consultation Requests** shows the FIFO queue; Accept or
  Reject. Accepted ones move to **Accepted Appointments**, where you can
  mark them **Completed**.
- As Admin, use **All Appointments** to search/sort every appointment,
  **Reports** to generate a summary, and **Activity Log** to monitor
  everything happening in the system.

## Running from the command line (optional, if you have a JDK)

```
cd FinalProject
javac -d build $(find src -name "*.java")
cd build
java consultation.Main
```
(Run this from the project root so the `data` folder is found; or copy the
`data` folder next to wherever you run `java` from.)
